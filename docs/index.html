XML-TEI → Livre web + LaTEI statique, élégant et réversible

Générez un livre web complet à partir d’un fichier XML-TEI (TEI Commons-Publishing), d’un dossier d’assets et d’une interface graphique simple.

Impressions transforme un volume éditorial structuré en un livre web savant : page d’accueil, navigation par chapitres ou contributions, métadonnées, quatrième de couverture, PDF, citations, illustrations agrandissables et export de pages HTML statiques prêtes à être mises en ligne. Il peut aussi produire un fichier LaTEI — un LaTeX contrôlé, modifiable et réversible — permettant d’ajuster finement le PDF puis de restaurer un XML Métopes propre.

Vous pouvez accéder au projet sur le repo Github d'Impressions ou télécharger l'exécutable Windows ci-dessous.

Interface graphique

L’interface rassemble l’essentiel : sélection du XML maître, ajout des fichiers utiles, choix des assets, génération du site et consultation du journal de build.

Principe et objectif

Un outil de publication sobre, universitaire et lisible pour transformer un volume XML-TEI (TEI Commons-Publishing) en livre web.

1
Une source structurée
Le fichier XML-TEI (TEI Commons-Publishing) constitue la source principale du livre : titre, structure, divisions, auteurs, notes, éléments éditoriaux.
2
Des assets complémentaires
Couverture, logos, PDF, quatrième de couverture et autres ressources peuvent être ajoutés via un dossier d’assets clairement organisé.
3
Un livre web statique
Impressions génère un site HTML statique, léger, robuste, rapide à afficher et facile à maintenir ou à déposer sur un serveur web.

Exemple de rendu

Impressions ne produit pas seulement une interface de travail : il génère un véritable livre web savant, structuré, lisible et directement publiable.

Cette capture peut montrer, selon ton choix, la page d’accueil d’un livre, une contribution, un apparat de notes, une illustration agrandissable ou encore le bloc de citabilité. L’idée est de donner immédiatement à voir la qualité du rendu final.

Déploiement pas à pas

Le scénario le plus courant : choisir les sources → lancer le build → vérifier le site → publier.

1 Sélectionner le fichier XML maître

Choisissez le fichier XML qui sert de point d’entrée au volume.

2 Ajouter les fichiers XML utiles

Selon les cas, plusieurs fichiers XML peuvent être associés à la génération.

3 Indiquer le dossier d’assets

Le dossier d’assets permet d’ajouter couverture, logos, PDF, quatrième et autres ressources du volume.

4 Choisir le dossier de sortie

Le build génère le livre web dans un dossier de sortie autonome.

5 Lancer la génération

Impressions produit alors les pages HTML, copie les ressources utiles et génère un rapport de build.

6 Vérifier le livre généré

On contrôle la page d’accueil, la navigation, les téléchargements, la couverture, les citations et les illustrations.

Bon réflexe : relire immédiatement la page d’accueil et quelques contributions avant mise en ligne.

Ce qu’Impressions génère

Un dossier de livre web prêt à être servi sur le web, sans base de données ni couche applicative complexe.

Selon les options et les ressources disponibles, vous obtenez notamment :

  • index.html : page de présentation du volume ;
  • une page HTML par chapitre ou contribution ;
  • book.normalized.xml : XML normalisé ;
  • assets/ : CSS, JavaScript, images, logos, PDF, etc. ;
  • build_report.txt : rapport de génération ;
  • book.tex : fichier LaTEI éditable, si l’export LaTEI est activé ;
  • book.pdf : PDF issu du LaTEI, si la compilation PDF est activée ;
  • des métadonnées utiles à la consultation et à la citation.
Résultat : un livre web savant, autonome, léger et facilement publiable.

LaTEI : mise en page PDF et réversibilité XML

Impressions peut produire un LaTeX contrôlé, éditable à la main, compilable en PDF et restaurable vers XML Métopes.

La fonctionnalité LaTEI ajoute une couche de correction d’épreuves à la chaîne de publication. À partir du XML Métopes, Impressions peut générer un fichier .latei.tex : il s’agit d’un LaTeX sémantique, structuré par des commandes contrôlées, que l’on peut ouvrir, corriger, compiler en PDF, puis relire pour restaurer un XML propre. Le détail des corrections éditoriales autorisées est réuni dans le guide des corrections éditoriales LaTEI (PDF).

1
Exporter vers LaTEI
Les éléments éditoriaux du XML sont représentés par des commandes comme \teiP, \teiHead, \teiNote ou \teiFigure. Elles portent le contenu restaurable vers XML.
2
Corriger le PDF
Les éditrices et éditeurs peuvent corriger le texte dans les accolades et utiliser des commandes \latei... pour la mise en page : ajouter un blanc, supprimer un alinéa, forcer un saut de page ou éviter une coupure.
3
Restaurer le XML
Le LaTEI modifié peut être relu par Impressions. Les corrections de contenu sont conservées, mais les commandes de mise en page \latei... disparaissent au retour XML.
Principe essentiel : les commandes \tei... portent le contenu éditorial réversible ; les commandes \latei... portent uniquement la mise en page PDF et ne sont pas exportées vers XML. 
XML Métopes → LaTEI modifiable → PDF
                 ↓
          retour possible vers XML Métopes

Cette architecture évite la double correction : le PDF peut être ajusté finement dans un environnement LaTeX contrôlé, tout en conservant la possibilité de revenir vers un XML sémantique utilisable pour la diffusion, l’archivage ou d’autres chaînes éditoriales.

Exemples de corrections autorisées

\teiP[xmlid={p-111}]{Premier paragraphe.}

\lateiVSpace{small}

\teiP[xmlid={p-112}]{Second paragraphe avec un peu plus d’espace.}
\lateiNoIndent{
  \teiP[xmlid={p-113}]{Ce paragraphe ne doit pas avoir d’alinéa.}
}
À ne pas faire : ne pas écrire directement du LaTeX brut comme \noindent, \vspace, \newpage ou \clearpage dans la zone éditoriale. Utiliser uniquement les commandes \latei... documentées.

FAQ

Quelques réponses rapides pour une première prise en main.

Faut-il connaître le web pour utiliser Impressions ?

Non. Le principe est de s’appuyer sur une interface graphique simple et sur des sources déjà préparées en amont.

Le XML est-il obligatoire ?

Oui : Impressions a été conçu pour partir d’un XML-TEI (TEI Commons-Publishing) structuré.

Peut-on ajouter une quatrième de couverture hors XML ?

Oui. Impressions peut la prendre dans assets/quatrieme/, avec priorité au Markdown, puis repli sur HTML ou TXT.

Peut-on joindre un PDF du volume ?

Oui. Si un PDF est présent dans le bon dossier d’assets, il peut être proposé au téléchargement sur la page d’accueil.
